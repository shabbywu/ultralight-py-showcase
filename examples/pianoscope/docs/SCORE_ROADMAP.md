# PianoScope 五线谱与演奏评估需求规划

版本：规划 v1.1 · 2026-10-18。状态：原始需求与实施方案；P1 已按授权实施，实际交付与验收见 [v1.1 验收记录](V1_1_VALIDATION.md)，P2 仍仅规划。

本文件是本地 `.tmp/pianoscope/specs/ultralight_pianoscope_spec_v1.1.html` 的配套规划；v1.1 HTML 为增量需求基准，已有功能契约参见 v1.0，现有行为与状态参见应用 README／验收记录。P0 的真实音频、原生 binding、时钟和离线约束继续适用。P0 尚待完成的性能与人工验收见 [VALIDATION.md](VALIDATION.md)，不因新规划而视为完成。

## 1. 已确认的产品目标

用户确认：

1. 从当前导入的 MIDI 生成钢琴五线谱，导出 **PDF + MusicXML**。PDF 用于打印／分享，MusicXML 用于在制谱软件继续编辑。
2. “按五线谱的形式弹奏”指 **播放原曲时展示五线谱、跟随高亮，供用户对照练习**。
3. 本轮不采集用户演奏，不做麦克风实时识别。后续 P2 可改为导入已有演奏音轨，与原曲匹配、评分和定位错误。

MIDI 转谱的产品定位为“生成可读的练习谱”。MIDI 中没有完整的原谱排版、声部和演奏法信息；同一演奏可能存在多种合理记谱结果。不能宣称还原出版原谱或任意 MIDI 一键得到准确专业谱。

| 阶段 | 交付结果 | 边界 |
| --- | --- | --- |
| P0 收尾 | 保持现有播放器可用，建立新版布局性能基线，补人工验收 | 与新功能分别记录状态 |
| P1-A 制谱与导出 | MIDI → 可预览的双谱表练习谱 → PDF / MusicXML | 主线；不以外部制谱软件作为运行依赖 |
| P1-B 五线谱跟谱 | 同一份练习谱在原曲播放时定位、高亮、跟随、跳转、循环 | 复用现有真实音频，不引入第二个播放器 |
| P2 规划储备 | 导入已有演奏文件 → 离线分析 → 原曲匹配 → 分项评分和错误位置 | 本轮不开发；先验证识别与对齐能力 |
| 独立 backlog | 外部 MusicXML 导入、完整谱面编辑、PNG 导出、发行打包 | 不自动并入此次 P1；包装发行仍另排 |
| 延后且不纳入本次交付 | 实时键盘／MIDI 演奏采集、计算机键盘演奏、麦克风录音与实时识别 | 不为这些入口做占位产品流程 |

## 2. 用户流程与界面

### 2.1 生成并导出练习谱

打开 MIDI → 选择“五线谱” → 确认制谱选项 → 生成／预览 → 导出 PDF 或 MusicXML → 原生保存对话框。

- 初次生成显示默认选项与必要的待确认项；再次进入复用当前版本。
- 选项包含谱表分配、节奏量化、拍号／调号来源、弱起设置。修改后先生成预览，应用成功才替换旧谱。
- 预览应能看到小节号、分手／谱表结果和量化提示；能到达具体待检查的小节。
- 导出默认包含全曲全部选定制谱轨道。试听静音／独奏／单手模式不隐式改变导出内容；若导出选定轨道，必须在导出范围中明确选择并显示计数。
- PDF 第一版采用 A4 竖向、自动分页、黑白谱面、曲名和页码；MusicXML 使用未压缩 `.musicxml`。不把 PNG／MXL／可变纸张排版作为首版必交项。
- 导出采用原曲速度和已应用制谱设置，不采用当前 0.5×／0.75× 试听速度。屏幕和打印允许换行分页不同，音高、节奏、谱表和小节语义必须一致。
- 保存取消不产生文件、不改变播放器状态；覆盖遵循原生保存对话框，成功前不破坏已有目标文件。

### 2.2 对照五线谱练习

打开 MIDI → 生成五线谱 → 播放 → 当前音符／和弦和小节定位 → 减速、跳转、A–B 循环 → 用户在自己的钢琴上对照练习。

- 主区域增加“下落音符 / 五线谱”视图切换；原有键盘模式、音名、触键线仍在主区域。触键线设置仅作用于下落视图。
- 品牌与打开文件继续放在左侧栏；制谱与导出入口可放在侧栏文件区。保留最近的小屏布局，不恢复大顶部 header。
- 五线谱模式优先保证一整行钢琴双谱表与播放控制可读。800×600 时键盘可折叠，频谱默认折叠；不能靠无限缩小谱面同时塞入所有面板。
- 默认显示当前谱行和后续内容；自动跟随可关闭。用户手动翻页／滚动后暂停自动跟随，通过“回到当前”恢复，避免与用户争抢视图。
- 屏幕普通音符以高对比度显示；播放高亮复用左手薄荷绿、右手暖金、未分配灰紫。手别未知时不冒充已确认。
- 暂停保留定位游标，清除“正在发声”高亮；踏板尾音与按住音符区分。停止回到原曲开头并保留 A–B 选区。
- 不出现“等待弹奏”“识别中”“演奏得分”等暗示已接入输入采集的文案。

## 3. P1-A：制谱功能需求

| ID | 需求 | 首版边界／验收要点 |
| --- | --- | --- |
| NS-01 | 从当前 MIDI 建立独立记谱模型 | 不改原始演奏事件或 PCM；每个记谱事件可追溯源音符 |
| NS-02 | 钢琴双谱表 | 上谱表默认高音谱号、下谱表默认低音谱号；支持加线。谱表分配与左右手标签分开 |
| NS-03 | 节奏量化 | 支持“常规节奏（最细十六分）”与“含八分三连音”两种明确配置；预览量化影响 |
| NS-04 | 节奏符号 | 全、二分、四分、八分、十六分音符与相应休止；附点、八分三连音；跨拍／跨小节延音线与合理连梁 |
| NS-05 | 和弦与声部 | 同起点异时值不能强制合成同一时值和弦；首版每谱表最多两个独立声部，复杂情况明确报告 |
| NS-06 | 拍号、调号、速度 | 使用源 MIDI 元数据；缺失时使用可确认的默认值，保留来源标记。支持节内速度变化 |
| NS-07 | 小节与弱起 | 常见 2/4、3/4、4/4、6/8 及小节边界的拍号变化；弱起由用户确认长度；小节号唯一定位 |
| NS-08 | 谱表分配预览 | 优先提供已确认手别／轨道映射作为建议，也可按音高初分；未分配音符计数可见，应用前检查 |
| NS-09 | 导出 PDF | 多页可打印，无缺失谱号／符头／中文标题，无裁切，页码正确 |
| NS-10 | 导出 MusicXML | 结构可校验、可在独立制谱阅读器打开编辑；音高、声部、小节时值与记谱模型一致 |
| NS-11 | 后台作业与恢复 | 真实进度、取消、版本隔离；失败保留旧谱和当前可播放曲目 |
| NS-12 | 制谱边界可见 | 超出声部／节奏能力时定位问题并拒绝提交错误谱；不能静默丢音或展示为成功 |

### 3.1 记谱规则必须先固定

- **演奏与记谱分离**：原始起音／松键保留真实时间；谱面时值使用有理数四分音符单位。量化只改变记谱结果。
- **量化不能静默删音**：对齐后短音塌缩、同音碰撞、负时值、过大偏移均记录具体音符和小节。简单配置无法表示时提示换配置／调整范围；不能把不能处理的音符删除。
- **稳定量化**：同一 MIDI、相同配置和相同依赖版本应得到相同结构；不能跨帧随机改变声部或升降号。第一版不承诺自由速度现场演奏的自动节奏恢复。
- **谱表不等于手别**：左手可弹高音、右手可弹低音；选择下谱表不能改写手别标签，修正谱表也不能自动重合成声音。保持两套独立字段。
- **延音与踏板**：用原始松键时间推导记谱音长，不把踏板声尾写成持续按键。首版不自动推断连奏线、指法、力度术语；踏板演奏仍由现有音频内核还原。
- **调号与等音拼写**：保留源调号与其变化；缺失时默认“无升降调号＋临时记号”，标注为默认，可由用户选择调号重生成；不宣称 C 大调就是原曲真实调性。
- **弱起与异常拍号**：不把开头休止直接认定为弱起；弱起必须确认。小节中途改拍号、无拍点自由节奏等超出首版规则时明确给出检查位置。
- **重复音与连音**：重新起音必须保留为两个演奏事件；跨小节同一持续音拆分成延音线链。同键双手、同音重叠不得通过集合去重丢失事件。
- **复杂作品处理**：超过每谱表两个声部、超细节奏或无法分解的复合连音，允许调整制谱轨道／配置后再试；不承诺支持全部合法 MIDI 的完整制谱。
- **信息守恒报告**：制谱范围内每个源音符必须有记谱映射或明确的阻断原因。应用成功的版本不能含未说明的丢音、合并或改变音高。

### 3.2 边界与冻结条件

- 无弱起时首小节从 tick 0 开始，开头空白写休止；用户确认弱起后独立记录实际长度。尾小节默认以休止补齐，不能补出发声音符；空曲拒绝制谱并说明原因。
- 量化配置须在 M2 前固定网格、起止取整、等距决胜规则、最短时值和最大偏移容差（以拍为单位），写入配置版本和 fixtures；超容差阻断应用。不能使用未定义的“微小偏移”作为验收标准。
- 生成期间音频继续播放。手别或制谱轨道等依赖变更使预览过期；试听静音、音量变化不使其过期。换曲后旧结果不得覆盖新曲。

## 4. P1-B：五线谱跟谱功能需求

| ID | 需求 | 契约 |
| --- | --- | --- |
| SF-01 | 当前音符／和弦高亮 | 从原播放器源秒和真实 active 状态映射到谱面；同一时刻的多个音符都能定位 |
| SF-02 | 小节与拍定位 | tempo map 换算音乐位置；不能按整页 x 坐标匀速推进 |
| SF-03 | 自动跟随 | 在谱行／页切换时保持当前音乐位置可见；手动浏览可暂停跟随并恢复 |
| SF-04 | 点击跳转 | 点击符头定位其源音符；延音线后段定位对应演奏区间；点击小节／休止定位对应时间 |
| SF-05 | 变速与循环复用 | 支持现有 0.5×／0.75×／1×、A–B、seek；谱面不重建 PCM，循环回绕后正确回到对应谱行 |
| SF-06 | 轨道与手别试听 | 谱面结构保持；听不到的音符弱化，不显示发声高亮；不因此隐式改变导出范围 |
| SF-07 | 视图切换连续 | 下落／五线谱、谱面缩放、键盘开关、侧栏开关不暂停、不重置时间，不丢循环 |
| SF-08 | 延音线与踏板可区分 | 一个源音符的多段符头不计为多次起音；声音尾部不冒充按住 |
| SF-09 | 制谱失败可恢复 | 当前 MIDI 仍可在下落视图正常播放；保留已成功的旧谱，明确版本已过期或不可用 |

### 4.1 三类时间与映射

1. **原始音乐位置**：整数 tick / PPQN、tempo map 与拍号定位。
2. **演奏时间**：原曲源秒、实际松键／踏板时刻；设备 DAC 时钟仍是播放唯一时钟。
3. **记谱位置**：量化后的小节、拍、谱表、声部、符头与延音线段。

三者通过数据映射连接。不能直接拿排版器导出的 MIDI／时间图替换原曲演奏时钟，也不能为了让谱面整齐而改动音频。

一个源音符可能因跨小节产生多个记谱符头；一个和弦／同音显示单元也可能对应多个源事件。映射必须支持一对多和多对一。延音线链的各段记录独立的原曲显示区间，首段从源起音开始，末段到源松键结束；中间分界将记谱拍位置换算为 tick，再经原曲 tempo map 换算为源秒，限制在源起音至松键区间内并保持单调；不能按总秒数等比分配。量化造成空区间时保留符头及来源映射，但不虚构发声高亮。所有推导边界记录来源。

点击及高亮均使用这些映射。跳转保留播放／暂停意图，并沿用 P0 的 A–B 范围钳制语义；不为五线谱新增一套跳转规则。小节游标依照原始拍位置与谱面拍点锚点插值；在非匀距排版、休止、换行、变拍时不能套用全曲线性 x 比例。量化造成的微小演奏偏移保留，音符发声状态优先于视觉拍点推断。

## 5. 现有代码基础与必须补充的数据

核对现有 `pianoscope/midi.py`：已有音高、力度、源秒起止、踏板声尾、手别、轨道、tempo map 和 meter map；当前 Note 未保留原始 tick，Score 未公开 PPQN，调号未解析保留，CC64 未作为完整控制时间线保存。

| 层 | 规划改动 | 目的 |
| --- | --- | --- |
| MIDI 模型 | 增加 PPQN、起音／松键 tick、tempo／meter 的 tick、调号事件；保留有效原始来源标识与 CC64 | 避免由 float 秒反推节奏，支持追溯 |
| 记谱模型 | 新增独立 NotationDocument | 存储有理数拍位置、声部、谱表、休止、和弦、延音线、警告 |
| 版本 | 独立 notation_revision、layout_revision | 试听／音量不使谱面失效；换行缩放不使语义模型失效 |
| 映射 | source_note_id ↔ notation_event_id ↔ glyph_id | 跟谱、点击跳转、未来错误定位共同使用 |
| 排版产物 | 页／谱行底图、符头与小节几何清单 | 不在动画帧内重新排版或重复读取整曲 |
| 导出作业 | 固定记谱版本与范围快照，临时输出后发布 | 生成过程中换曲不导出错误版本 |

建议数据契约（规划示例，不是已实现 API）：

```text
NotationDocument:
  id, score_id, source_fingerprint, notation_revision
  options, measures, events, warnings, source_note_index

NotationEvent:
  id, source_note_ids[], measure_id, staff, voice
  pitch_spelling, onset_qn, duration_qn, tie_group, hand
  source_display_spans[]

LayoutManifest:
  notation_id, notation_revision, layout_revision
  systems[], pages[], glyphs[{event_id, source_note_ids[], page, system, bbox}]
```

- 有理数序列化为整数分子／分母；屏幕只消费有限数值几何和源时间，不自行推导乐理。
- 源音符 ID 在同一次加载与修订内稳定；跨加载持久引用使用源文件指纹＋事件来源，不能仅靠当前临时 `n0` 或曲名。
- 现有 `score.revision` 涉及音频／手别配置，新记谱缓存应按实际依赖签名更新，不能笼统地每次配置都重新制谱。
- 首版沿用 P0 文件／曲长保护；额外建立小节数、页数、排版内存和处理时间上限，数值在最小闭环实测后锁定。音符数量上限不代表这些音符都能无条件排版成功。

## 6. 技术路线与最小验证关卡

所有依赖仍由 Python 与本地资源承载，保持 `ultralight-py==0.5.0`、Python 3.10+、AppCore、`API("piano")`；不新增 HTTP／WebSocket／CDN、浏览器或 Node.js 运行时要求。

主线候选：自有记谱模型 → MusicXML → **Verovio Python 原生排版** → 本地谱面底图与几何 → Canvas 2D 显示／高亮；相同语义模型的打印排版 → SVG → **CairoSVG PDF** → 多页 PDF 合并。原曲音频继续使用既有 FluidSynth 与设备流。

这是基于官方能力文档形成的方案推断，尚未在此项目验证：

- Verovio 提供 Python toolkit、MusicXML 导入和 SVG 排版；其时间／元素接口可辅助检查，但不能当作原曲演奏时钟。[Verovio Python](https://book.verovio.org/installing-or-building-from-sources/python.html)、[输入格式](https://book.verovio.org/toolkit-reference/input-formats.html)、[元素／时间接口](https://book.verovio.org/toolkit-reference/toolkit-methods.html)。
- `music21` 可作为记谱辅助候选，不直接二次导入 MIDI 代替现有模型。项目要保留 Python 3.10，不能直接选最新版；官方当前建议 Python 3.10 使用 9 系列，兼容版本须在关卡验证后固定。[官方兼容说明](https://github.com/cuthbertLab/music21/blob/master/README.md)、[MusicXML 输出接口](https://music21.org/music21docs/moduleReference/moduleMusicxmlM21ToXml.html)。
- CairoSVG 可将 SVG 转成 PDF，但引入 Cairo／FFI 原生依赖；谱号、符头、中文字体与多页组合须实际验证。不能只验证 SVG 能打开就宣称 PDF 可交付。[官方文档](https://cairosvg.org/documentation/index.html)。
- MusicXML 的 note ID、voice、staff、tie／tied 用于表达相关结构；布局引擎是否保留源 ID 必须实测，不能仅从格式支持推定。[MusicXML note](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/note/)。

**G0：先完成一个真实原生最小闭环，再承诺完整实施排期。**

1. 用已知小片段构造含双谱表、和弦、休止和跨小节延音线的 MusicXML。
2. 在现有 Python 3.10 环境原生排版，证明音符 ID、谱行／小节／符头几何能稳定对应。验证原生 SVG 几何提取与 Canvas 底图坐标一致的实际方法。
3. 在 AppCore 本地页面显示谱面，绑定真实源时钟高亮一个和弦，点击符头经 binding 执行真实 seek。

## 7. Binding 与任务契约草案

以下为待实现接口名称，实做时与现有 bridge 命名统一：

| 接口 | 返回／行为 |
| --- | --- |
| `begin_notation(options)` | 提交预览作业；快照锁定源曲与配置，返回作业 ID；不替换已应用版本、不停止音频 |
| `apply_notation(preview_id, expected_source_revision)` | 校验源依赖与预览版本，原子发布；过期拒绝应用，失败保留旧谱 |
| `get_notation()` | 返回元数据、版本、页／小节数量、warnings、状态；不每帧传全曲 |
| `get_notation_layout(notation_id, layout_options)` | 返回排版作业 ID；结果清单按页分页读取本地资源 token 和几何映射，限制单次载荷；缩放只重排版 |
| `choose_score_export(format)` | 原生保存对话框返回受限目标 token，取消返回 null |
| `begin_score_export(notation_id, format, target_token)` | 锁定已应用版本导出；返回作业 ID，支持进度与取消 |

复用现有作业查询／取消模式；区分音频作业与记谱／导出作业，不能只有一个全局 busy 标志导致播放失效。所有晚到结果校验 score_id／notation_revision／layout_revision 与关闭状态。本地资源 token 只读取本作业产物，不开放任意文件能力。保存对话框返回后、开始导出前再次校验已应用版本；旧目标 token 不得用于新曲目。作业锁定快照后可完成原版本导出，结果明确标识曲目与版本；取消在原子发布前生效，发布后返回已完成，不误报取消。预览状态为 generating／preview_ready／applied／stale／failed／cancelled，与播放器状态独立。

错误至少区分：`NOTATION_OPTIONS_REQUIRED`、`NOTATION_TOO_COMPLEX`、`NOTATION_ENGINE_UNAVAILABLE`、`NOTATION_STALE`、`EXPORT_FAILED`。用户看到中文原因与可恢复操作，堆栈留在诊断日志。

## 10. P2：导入演奏文件做离线评估（本轮不实现）

### 10.1 范围重设

输入为当前原曲 MIDI，加上用户已录好的独奏钢琴音频文件；首个验证格式建议 PCM WAV。也可在后续评估导入已有演奏 MIDI 文件，但不新增实时 MIDI 输入采集。

本阶段不内置录音、不读取麦克风、不监听键盘演奏；不上传音频、不做实时反馈。背景伴奏、多人合奏、任意乐器和复杂噪声录音不作为首个可评分范围。

流程：导入演奏文件 → 音频质量检查 → 音符／起音分析 → 与原曲对齐 → 显示可评估覆盖率和置信度 → 分项得分 → 按小节／源音符查看问题及回听。

### 10.2 匹配与评分契约草案

- 参考真值使用原曲 MIDI 的演奏事件。制谱量化不能改变评分标准；错误位置经 source_note_id 映射到当前五线谱。
- 先估计开头偏移、全局速度差和有效演奏片段，再做受约束的局部对齐。必须容许漏音／多音；不能强制每个音符匹配成功。
- 区分“跟随对齐”与“节奏评分”：弹性对齐可帮助定位，但不能把所有局部早晚都拉直后给满分。先明确练习任务采用原速目标还是已选慢速目标，再计算相应基线偏差。
- 音频相似度／色度相似度可辅助找段落，不能直接当成逐音准确率。重音、踏板、泛音和同音重叠会影响识别，尤其要验证双手复音。
- 至少区分音高匹配、漏音、多音、起音早／晚、持续时长；持续时长项在踏板影响或低置信度时允许不评分。
- 同音替换、错音与额外音的归类规则保持确定性；同一错误不能同时算多次扣分。多余音没有源 note_id 时定位到相邻小节和演奏时间。
- 同一源长音在谱面拆成多个符头，只评分一次；同音重新起音保留多次事件。
- 逐音匹配使用一对一约束，和弦按组成音分别计数；同一个演奏起音不能匹配多个参考起音。相同音高的重叠事件保留独立身份，不通过去重提高匹配率。

建议首轮报告指标：

```text
匹配准确率 precision = 正确匹配的演奏起音数 / 可评估演奏起音总数
音符召回率 recall = 正确匹配的参考起音数 / 可评估区域内参考起音总数
音符匹配分 F1 = 2 × precision × recall / (precision + recall)
节奏偏差 = 匹配音符相对约定速度基线的起音偏差分布
事件覆盖率 = 可评估区域内参考起音总数 / 用户选定范围参考起音总数
时间覆盖率 = 可评估参考区间总时长 / 用户选定参考范围时长
```

可评估区域根据音频质量与识别置信度独立确定，不能根据匹配是否成功筛选；区域内漏音仍计入 recall 分母，多音计入 precision 分母。局部 F1 必须同时展示两种覆盖率；低于预先版本化的覆盖率门槛不提供总分。

“正确匹配”需同时满足已版本化的音高与时间容差；分母为零时显示“无法评分”。部分演奏的参考范围要先确认，不能悄悄只选最接近的一小段。未评估区域必须明确显示，不把低置信区域视为全对或全错。总分权重、阈值和通过分在有真实标注集后确定，当前不设一个未经校准的固定百分比承诺。

### 10.3 错误定位与展示

每项结果记录：原曲时间、演奏时间、小节／拍、source_note_id（若有）、错误类型、期望音／识别音、置信度与可回听区间。界面可以跳到对应谱行、突出符头并对比回听；对识别不可靠的位置显示“需确认”，允许纠正，不直接断言用户弹错。

### 10.4 P2 启动关卡

1. 先用已知 MIDI 注入错音、漏音、多音、延迟、变速和停顿，验证对齐与计分逻辑；这只证明匹配算法，不证明录音识别能力。
2. 分别用真实 SoundFont 合成测试、实际单音录音、实际双手钢琴录音验证识别。必须有人工标注，与评估集分离校准阈值。
3. 记录音高／起音 precision、recall、F1、错误定位精度和可评估覆盖率；报告踏板、设备、噪声和曲目复杂度的适用范围，不只报告自合成样本。
4. 如引入本地转录模型，先验证 Python／平台依赖、模型文件大小、许可、离线可用性与耗时。不得运行时默认下载模型或把录音传到服务端。
5. 识别质量不足时只交付已验证的有限范围（例如单音片段），不能把相似度曲线包装成可靠的双手逐音评分。

P2 的实时输入采集仍作为单独后续议题；离线评估完成不代表键盘输入或麦克风识别已完成。
